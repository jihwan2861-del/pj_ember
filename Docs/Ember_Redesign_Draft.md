# Ember 재설계 초안 v0.1

작성일: 2026-10-02.
상태: 논의용 초안. “셀레스트처럼 정밀 이동으로 퍼즐을 돌파하고, 호텔 추격전 같은 추격 구간을 포함한다”는 사용자 방향은 확인되었다. 조작은 WASD·Shift·Space·마우스로 바꾸는 계획이며, 점화는 Project Arrow의 활처럼 불씨를 겨누어 발사하는 방향이다. 세부 능력·수치·방 구성은 검증할 제안이다.

## 다시 설계하는 목적

기능과 수치가 세션마다 추가·변경되면서 게임의 핵심, 조작 규칙, 완성 범위가 흐려졌다. 새 기획의 목표는 기능을 많이 만드는 것이 아니라 반복해서 즐길 수 있는 작은 게임을 완성하는 것이다.

기준 자료는 현재 작업 파일, `Docs/Ember_Reverse_Design_Document.md`, `Docs/AI/PlayerMovementAnalysis.md`다. 개발 현황 문서의 신화 중심 5개 스테이지와 최신 역기획서의 작은 불꽃 모험·4개 스테이지는 서로 다른 방향이므로 둘을 합쳐 확정하지 않는다. 이 초안은 최신 역기획서의 방향을 우선 참고한다.

## 제안하는 게임의 중심

**작은 불꽃이 점프·점화·흡수·발사를 연결해 경로 퍼즐을 돌파하고, 추격자의 공격을 피해 같은 동작을 더 빠르고 정밀하게 실행하는 2D 플랫포머.**

플레이의 중심 동사는 세 가지다.

1. **밝힌다:** 불씨를 겨누어 발사하고, 맞은 가연물에서 불을 퍼뜨려 이동 가능한 거점을 만든다.
2. **들어간다:** 목표 불꽃을 선택하고 안전한 경로로 흡수 이동한다.
3. **튀어나온다:** 불 안에서 방향을 정하고 발사해 다음 지형이나 거점에 도달한다.

점프는 이 세 행동을 이어주는 기본 이동이다. 핵심 감정은 “길을 읽고, 내 조작으로 그 길을 돌파했다”이며 추격 구간에서는 “알고 있는 길을 압박 속에서도 해냈다”로 강화한다.

**확인된 중심 비중은 정밀 이동으로 푸는 환경 퍼즐이다.** 멈춰서 스위치 순서를 오래 생각하는 퍼즐보다, 이동 경로와 행동 순서를 읽은 뒤 직접 실행하는 퍼즐을 우선한다. 사용자가 원하는 추격전도 첫 작은 완성 구간에 포함하여 핵심 조작이 압박 상황에서 성립하는지 일찍 검증한다.

예시: 점프로 횃불 가까이 접근 → 공중에서 점화 → 흡수로 위험 구간 횡단 → 대각선 발사로 천장 아래 통과 → 착지 또는 다음 불꽃 연결. 퍼즐의 답은 행동 순서와 이동 경로이며, 실행에는 타이밍과 위치 조절이 필요하다.

## 첫 완성 범위

전체 스테이지 수와 총 플레이타임은 지금 확정하지 않는다. 먼저 시작·학습·도전·마무리가 연결된 **5개 방, 약 5~10분 분량을 목표로 하는 작은 완성 구간**을 만든다. 실제 분량은 테스트 후 조정한다.

포함할 요소:

- 기본 이동·가변 점프·입력 버퍼·코요테 타임
- 조준한 불씨 발사에 의한 점화, 불꽃 흡수, 불꽃에서의 플레이어 발사
- 횃불과 이동 블록 또는 횃불 문 중 한 종류의 환경 장치
- 위험물, 방 시작 체크포인트, 빠른 재시도
- 방 카메라, 목적지 안내, 필수 효과음과 애니메이션
- 선택 도전 하나와 명확한 끝 화면
- 익힌 이동을 압박 속에서 실행하는 짧은 추격 방 1개

첫 구간에서 보류할 요소:

- C→Z 자유 대시와 C→X 조준 사격의 필수화
- 벽 등반, 스윙, 자유 비행, 상승하는 물, 복잡한 불 전파 퍼즐
- 전투, 보스, 성장 트리, 장편 서사
- 60개 방 또는 여러 스테이지의 동시 제작

보류는 기존 구현 삭제를 뜻하지 않는다. 해당 능력이 있어야만 재미가 성립하는지 따로 검증한다.

## 조작 제안

| 입력 | 일반 상태 | 불꽃 내부 |
|---|---|---|
| WASD | 좌우 이동·이동 방향 입력 | 플레이어 발사 방향 선택 |
| Space | 점프 | 플레이어 발사 |
| Shift | 표시된 불꽃으로 흡수 | 표시된 다음 불꽃으로 흡수 |
| 마우스 | 불씨 조준·흡수 대상 선택 | 다음 흡수 대상 선택 |
| 왼쪽 버튼 | 불씨 발사 준비/발사 — 상세 조작 미정 | 사용 가능 여부 미정 |
| R | 현재 방 재시작 | 현재 방 재시작 |

사용자가 제시한 점화 방향은 부채꼴 화염이 아니라 **활처럼 조준하여 불씨를 발사하는 방식**이다. 아래는 그 의도를 구체화한 비교 제안이며 Project Arrow의 정확한 입력 구현을 확인한 사양은 아니다.

- 첫 비교안: 왼쪽 버튼을 누르고 조준하며, 놓을 때 불씨를 발사한다.
- 충전으로 사거리/속도를 바꿀지, 고정 속도로 발사할지는 미정이다. 이동 중 빠른 사격과 퍼즐용 신중한 사격을 모두 평가한다.
- 궤적은 약한 중력의 곡선을 후보로 둔다. 직선 발사와 같은 방에서 비교하며 곡선이 필수라고 확정하지 않는다.
- 조준 중 이동·점프를 허용하는 안을 우선 검증한다. 긴 강제 정지나 항상 적용되는 슬로모션은 추격 압박과 함께 평가한다.
- 발사된 불씨가 의도된 가연물에 닿으면 점화되고, 연결된 가연물을 따라 불이 전파되어 다음 거점이 열린다. 불을 퍼뜨리는 인상은 발사체와 점화 후 전파를 함께 설계한다.
- WASD의 수평 이동과 마우스 조준은 분리한다. Shift의 대상은 사전에 표시하고, 커서와 가까운 유효 거점을 고르는 규칙을 검증한다.

기존 C 링과 링 중 대시·사격 조합은 최종 조작으로 계승하지 않는다. 필요한 역할이 남는지 비교 기준으로만 보존한다. 플레이어가 불에서 튀어나오는 발사와 마우스로 쏘는 불씨 발사는 다른 행동으로 명확히 구분한다.

이단점프는 현재 구현을 비교 기준으로 유지하되 최종 필수 능력으로 확정하지 않는다. 불꽃 거점을 우회하는 수단이 되는지, 실패 복구에 도움이 되는지 같은 방에서 단일 점프와 비교한다. 새 조작은 검증 전까지 기존 조작을 대체하지 않는다.

## 핵심 규칙 제안

### 기본 이동

- 수평 입력과 조준 벡터를 분리하여 상하키 때문에 달리기가 느려지지 않도록 한다.
- 모든 테스트 방은 하나의 이동 설정을 공유한다. 방마다 속도를 바꾸어 난이도를 맞추지 않는다.
- 코요테·버퍼는 현재 0.12초를 출발점으로 사용하고 체감 검증 후 조정한다.
- 일반 점프와 불꽃 발사는 서로 다른 역할을 가진다. 점프는 위치 조정, 발사는 큰 간격과 방향 전환이다.
- 자동 보정은 입력 의도를 보존한다. 큰 각도 변경으로 다른 길에 보내는 보정은 핵심 규칙으로 확정하지 않는다.

### 점화와 거점

- 이동 거점으로 사용할 수 있는 불꽃과 장식 불꽃을 시각적으로 구별한다.
- 첫 구간의 불꽃 거점은 점화되면 꺼지지 않는다. 시간 제한과 물에 의한 소화는 이후 후보로 둔다.
- 전파가 있는 가연물은 범위·시간과 연결을 플레이어가 읽을 수 있어야 한다. 첫 구간은 수동 점화부터 가르친다.
- 점화 자원은 비교할 결정이다. 현재의 접지/불꽃 진입 시 회복 규칙을 기준으로, 반복 사용 제한이 퍼즐을 만드는지 단순 입력 부담인지 평가한다.

### 흡수

- 현재 선택 목표를 이동 전에 명확하게 표시한다.
- 범위·경로·도착 공간이 유효한 목표만 “이동 가능” 표시를 한다. 막힌 목표도 표시한다면 다른 색과 짧은 실패 피드백으로 구분한다.
- 안내선은 실제 이동 경로를 설명해야 한다. 경로 검사와 실제 충돌 크기가 다르면 같은 통과 가능 규칙으로 정리한다.
- 장애물 관통은 허용하지 않는다. 경유점 자동 탐색은 좁은 모서리 보조로 한정할지 검증한다.

### 발사

- 방향 입력이 없을 때의 동작을 항상 일관되게 안내한다. 비교 기준은 현재의 위쪽 발사다.
- 방향은 키보드 8방향을 기준으로 예측 가능하게 만든다.
- 발사 직후 제어 제한은 조작감을 검증한 뒤 정한다. 0.25초 제한을 무조건 계승하지 않는다.
- 벽 근처 발사와 콜라이더 복귀에서 안전한 위치를 보장한다.

### 죽음과 재시작

- 제안: 사망과 R은 같은 “현재 방 시작 상태”를 복원한다. 플레이어, 점화 상태, 이동 블록, 문, 임시 투사체, 카메라와 시간 배율을 함께 다룬다.
- 이전 방 완료와 확보한 선택 수집품은 별도 진행 데이터로 유지한다.
- 첫 구간은 방 시작 체크포인트만 사용한다. 중간 체크포인트에서 퍼즐 상태를 저장하는 기능은 뒤로 미룬다.
- 위험물의 역할은 이동 도전이다. 해법을 이미 아는 퍼즐을 긴 대기와 연출로 매번 반복하게 만들지 않는다.

현재 코드에서는 PrototypeRoom 존재 여부에 따라 사망 때 불 초기화 여부가 달라질 수 있고, 방 재시작에서 이동 블록 ResetBlock은 호출되지 않는다. 새 규칙을 확정한 뒤 재시작 경로를 통합해야 한다.

## 5개 방 제안

| 방 | 목표 | 가르칠 것 | 배치와 통과 조건 |
|---|---|---|---|
| 1. 첫 불빛 | 기본 이동으로 출구 도달 | 걷기·짧은/긴 점프·재시도 | 안전한 바닥, 작은 단차, 낮은 천장. 실패해도 바로 복귀 |
| 2. 불 속으로 | 꺼진 횃불을 켜고 높은 출구로 발사 | C 점화→X 흡수→Z 발사 | 직접 점프로 닿지 않는 출구와 단일 횃불. 선택 목표가 분명함 |
| 3. 움직이며 밝힌다 | 점프 중 점화하고 다음 거점으로 연결 | 점화 위치·타이밍과 방향 선택 | 서서 점화하면 닿지 않는 횃불. 안전한 중간 착지와 선택 도전 |
| 4. 길을 읽는다 | 장치와 거점의 배치를 보고 연속 이동 | 점화→경로 변화→발사 순서 | 이동 블록 또는 문 한 종류. 5번 방에 나올 이동 패턴을 압박 없이 연습 |
| 5. 쫓기는 불꽃 | 익힌 동작을 연결해 추격에서 탈출 | 위험 예고를 읽으며 정밀 이동 | 짧은 추격 구간 2~3개로 구성. 새로운 필수 능력·불투명한 해법 추가 없음 |

각 방은 먼저 회색 블록으로 만든다. 방 크기와 거점 간격은 확정된 실제 이동 거리로 배치하고 스프라이트 높이에 맞춘 임의 튜닝은 피한다. 주 경로가 읽히고 안정된 후 장식을 추가한다.

## 추격전 제안 — 첫 번째 버전

### 추격자의 역할

캐릭터를 계속 따라붙는 그림자 또는 꺼뜨리는 존재를 후보로 둔다. 외형·서사는 미정이다. 첫 구현은 복잡한 자유 추적 AI보다 **방에 배치한 경로와 공격 지점**을 따라 움직이는 연출형 추격자로 만든다. 목표는 AI의 영리함이 아니라 플레이어에게 공정한 이동 압박을 주는 것이다.

기본 패턴 제안은 `등장 → 위치/방향 예고 → 직선 돌진 → 회복 → 다음 공격`이다. 공격 준비 중에는 이동 방향을 읽을 수 있고, 돌진을 시작하면 방향을 잠가 조작으로 회피할 수 있게 한다. 화면 밖에서 즉시 공격하거나 순간이동으로 플레이어를 잡는 규칙은 사용하지 않는다.

### 퍼즐과 압박을 결합하는 방식

방 4에서 해법과 동작을 가르치고, 방 5에서 같은 패턴을 압박 속에 실행한다. 추격자 회복 구간은 플레이어가 다음 경로를 읽는 시간이다. 예고 구간은 행동을 시작할 시간이고, 돌진 구간은 이동을 완수하거나 피할 시간이다.

예시 구간:

1. 횃불을 켜서 위험 바닥 위를 흡수로 넘는다.
2. 불에서 대각선 발사해 위쪽 발판에 도착하며 첫 돌진을 피한다.
3. 공중 점화로 다음 거점을 열고 짧은 점프 구간을 통과한다.
4. 이동 장치와 불꽃 경로를 연결해 마지막 돌진 뒤 출구로 빠진다.

주 경로에는 숨겨진 정답이나 새 키 조합을 넣지 않는다. 선택 도전은 먼저 일반 방에서 검증하고 추격 방의 필수 통과 조건으로 삼지 않는다.

### 불꽃 내부의 무한 대기 문제

추격 중 불 안에서 무한 대기할 수 있으면 압박이 사라진다. 반대로 흡수 즉시 잡히면 핵심 능력이 쓸모없어진다. 제안은 “들어갈 때 짧은 안전 여유를 주되, 추격자가 도착하면 해당 거점에 공격 예고가 생겨 떠나야 한다”이다. 정확한 체류·예고 시간은 거리와 실제 이동 시간으로 맞춘다.

일반 방에서는 충분히 방향을 고를 수 있게 하고, 추격 방에서는 거점이 영구 안전지대가 되지 않게 한다. 이 차이를 입장 시각 효과·소리·위험 표시로 설명한다. 안전 시간 숫자를 숨긴 채 갑자기 죽게 만들지 않는다. 추격자가 거점을 공격하더라도 출구에 필요한 유일한 경로를 영구 파괴하지 않도록 한다.

### 재시도와 카메라

첫 추격 버전은 짧은 방으로 만든다. 사망하면 추격 방의 시작 상태로 돌아가며 긴 등장 연출은 반복하지 않는다. 시작 상태에는 이전 학습 구간을 다시 풀지 않도록 필요한 초기 불꽃 상태를 명시한다. 구간이 길어지면 이후 중간 체크포인트의 상태 복원 규칙을 별도로 설계한다.

카메라는 플레이어뿐 아니라 다음 거점과 공격 예고가 보이도록 프레이밍한다. 강한 화면 흔들림이 정밀 입력과 목표 식별을 가리지 않도록 한다. 추격자의 등장 연출보다 이동 경로의 가독성을 우선한다.

### 테스트 기준

- 추격 없이도 방의 경로가 성립하며, 추격은 요구 이동의 속도·정밀도를 높인다.
- 플레이어가 왜 죽었는지 공격 방향·위험물·늦은 거점 이탈 중 하나로 설명할 수 있다.
- 공격 예고부터 피격까지의 시간은 요구 동작의 최소 실행 시간에 반응 여유를 더해 정한다.
- 흡수 속도가 빠르다는 이유로 추격자를 영구 따돌리거나, 느린 점프 구간 때문에 반드시 잡히는 상황을 피한다.
- 처음 실패한 사람이 재시도에서 동작을 개선할 수 있다. 실패마다 해법이나 목표가 바뀌지 않는다.
- 실제 테스트에서 경로 이해, 입력 실수, 충돌 문제, 공격 타이밍 문제를 나누어 기록한다.

## 개발 순서와 완료 기준

### 단계 1 — 규칙 정리

산출물: 핵심 비중, 조작표, 유지/보류 능력, 사망 복원 규칙을 확정한 기획 v1.
완료 조건: 같은 상황에서 어떤 키를 누르고 어떤 결과가 나오는지 설명이 충돌하지 않는다. 미정 사항을 기능 목록에 섞지 않는다.

### 단계 2 — 이동 검증 방

산출물: 동일 설정을 공유하는 플레이어와 점프·발사 거리 측정 구간.
검증: 좌우+상하 입력, 짧은/긴 점프, 코요테·착지 버퍼, 이단점프, 벽/천장 모서리, 작은 Collider 복원, 능력 전환 중 버튼 누름/놓음.
완료 조건: 입력과 이동 결과가 예측 가능하고, 반복 시도 시 규칙이 달라지지 않는다. 검증이 필요한 위험은 재현 기록 또는 해결 결과를 남긴다.

### 단계 3 — 핵심 2개 방

산출물: 1·2번 방을 연결한 프로토타입.
완료 조건: 점화→흡수→발사의 사용 이유를 레벨로 설명할 수 있다. 긴 텍스트 설명 없이 짧은 키 안내와 화면 피드백으로 이해되는지 테스트한다.

### 단계 4 — 5개 방 구간

산출물: 3~5번 방, 추격자 1패턴, 일관된 재시작, 출구/방 전환, 선택 도전.
완료 조건: 모든 방을 시작 상태에서 완주할 수 있고 사망·R·재입장 후 장치 상태가 꼬이지 않는다. 추격 없이 경로를 검증한 뒤 추격 압박을 더한다. 공격 예고와 거점 위험을 화면으로 읽을 수 있어야 한다.

### 단계 5 — 표현과 배포

산출물: 필요한 애니메이션·효과음·카메라·최소 메뉴·완료 화면·테스트 빌드.
완료 조건: 주요 위험과 목표가 배경에서 구별되고 사망 후 빠르게 재시도할 수 있다. 실제 시작 씬과 테스트 씬이 일치하며 저장/종료/재실행의 기대 동작을 확인한다.

기간은 아직 추정하지 않는다. 1·2번 방을 실제로 만드는 데 드는 시간과 수정량을 보고 남은 범위와 일정의 근거로 삼는다.

## 개발이 다시 흔들리지 않도록 할 기준

- 사용자와 합의한 기획 v1만 확정 사양으로 취급한다. 이 초안은 아직 기존 기획을 대체하지 않는다.
- 수치와 능력 규칙은 한곳에서 관리하고 씬별 덮어쓰기는 명시적 이유가 있을 때만 사용한다.
- 새 아이디어는 “후보 목록”에 넣고 현재 단계의 완료를 막지 않게 한다.
- 변경 기록에는 문제, 바꾼 규칙, 테스트 결과를 남긴다. 이전 세션의 추측을 확정 결정처럼 계승하지 않는다.
- 한 번에 이동·레벨·카메라·아트를 모두 변경하지 않는다. 어떤 변화가 체감에 영향을 줬는지 확인할 수 있는 단위로 진행한다.
- 단계별로 실제 플레이 가능한 결과를 검토한다. 문서가 완성됐다는 이유로 게임이 검증됐다고 보지 않는다.

## 다음에 정할 핵심 결정

1. 확인 완료: 정밀 이동으로 환경 퍼즐을 돌파하며 추격전을 포함한다. 점화는 활처럼 조준하는 불씨 발사이며, 조작은 WASD·Shift·Space·마우스 사용을 계획한다.
2. 미정: C 링 유지 여부. 공중 정지와 대시/사격 선택이 이동의 핵심인지, 점화만으로 충분한지 기준 방에서 비교한다.
3. 미정: 이단점프. 기본 능력인지, 불꽃 이동 학습을 약하게 만드는지 비교한다.
4. 미정: 목표 공개 범위와 일정. 행사·데모·개인 완성 중 무엇을 먼저 목표로 할지 정한다.

다음에는 기본 이동과 불꽃 능력의 역할을 정리하고 1·2번 기준 방을 구체화한다. 대시·이단점프는 실제 이동 퍼즐에 주는 역할로 유지 여부를 판단한다. 추격자는 기본 이동과 경로를 검증한 뒤 같은 규칙을 압박하는 방식으로 추가한다.
