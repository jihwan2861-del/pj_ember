# Ember 플레이어 이동 분석

분석일: 2026-10-02. 대상: `project Ember` Unity 프로젝트의 현재 작업 파일.
HEAD: `f93877e7dcf174bd68c2c7df98bbfb1305266300`. 컨트롤러와 프리팹·씬 등에 미커밋 변경이 있어 분석 대상은 이 커밋만이 아니라 작업 폴더의 실제 내용이다.

## 분석 범위와 결론

`FlamePlayerController`, `BurstDashAbility`, `PlayerAbilityInputRouter`, `PlayerAbilityUnlocks`, `FlameShotAbility`, `PlayerAnimatorDriver`, `PathMovingBlock`, 플레이어 프리팹 2종, 씬 4종, 물리·시간 설정을 읽었다. 코드·씬·프리팹은 변경하지 않았다. Unity Editor 실행, 플레이 모드 재현, 빌드, 프로파일링은 수행하지 않았다. 연결된 Unity MCP는 확인되지 않았다.

현재 이동은 Unity Rigidbody2D 기반의 플랫폼 이동에 이단점프와 불꽃 이동을 결합한 구조다. 지상 반응이 빠르고 공중 이동은 관성이 크지만 방향 반전은 빠르다. 셀레스트의 코요테 타임·정점 중력·모서리 보정을 일부 차용했지만, 점프 곡선과 대시 조작은 다르다. 주된 확인 대상은 수평 입력과 조준 입력의 결합, 자동 대시 방향 변경, 상태별 입력 샘플링, 접지·콜라이더 복원이다.

수치의 단위는 Unity 월드 단위/초, 가속도는 월드 단위/초²다. Y 양수는 위쪽이다. 셀레스트 픽셀 수치와 직접 배율 비교하지 않는다.

## 1. 상태와 입력·물리 갱신

컨트롤러의 FlameState는 Free, Bursting, BurstDashing, Travelling, Anchored 다섯 상태다. 점프와 낙하는 별도 상태가 아니라 Free 안에서 수직 속도와 bool로 처리한다.

| 상태 | 역할 | 물리 동작 |
|---|---|---|
| Free | 걷기·점프·낙하·공중 점프 | X 속도 직접 조절, 중력 배율 선택 |
| Bursting | C로 폭발 후 다음 행동 선택 | 속도 0, 중력 0, 기본 0.3초 |
| BurstDashing | 링에서 Z로 대시 | 방향×현재 대시 속도, 중력 0 |
| Travelling | X로 불꽃까지 이동 | MovePosition, 중력 0, 경로/장애물 검사 |
| Anchored | 불꽃 안에 머무름 | 위치 고정, 메인 콜라이더 비활성화 |

Update에서 Keyboard.current의 방향키·Z 입력을 읽고, FixedUpdate에서 실제 속도·타이머를 갱신한다. 능력 입력 Router는 실행 순서 100이므로 일반 컨트롤러 Update 이후에 X/C/Z의 상태별 의미를 처리하도록 구성되어 있다. 별도 InputAction 맵을 통해 이동하는 구조가 아니며 게임패드 입력 코드는 이 경로에서 발견되지 않았다.

기본 fixedDeltaTime은 0.02초, 즉 물리 50Hz다. 0.12초 유예는 약 6 물리 스텝이고, 0.06초 벽 속도 기억은 약 3 스텝이다. 렌더링 FPS와 물리 업데이트 횟수는 구분해야 한다.

근거: `FlamePlayerController.cs:255`, `:285`; `PlayerAbilityInputRouter.cs:6`, `:23`; `ProjectSettings/TimeManager.asset`.

## 2. 수평 이동과 조작감

기본 이동은 `Mathf.MoveTowards(vx, horizontalInput × moveSpeed, acceleration × dt)`다.

| 조건 | 가속/감속 |
|---|---:|
| 지상에서 같은 방향 또는 정지에서 출발 | 65 |
| 지상에서 입력 없음 | 85 |
| 공중에서 같은 방향 또는 정지에서 출발 | 22 |
| 공중에서 입력 없음 | 14 |
| 현재 속도 반대 방향 입력 | 95 — 지상·공중 공통 |

이동 5 기준의 연속시간 근사는 지상 0→5 약 0.077초, 지상 5→0 약 0.059초, 공중 0→5 약 0.227초, 공중 5→0 약 0.357초다. 실제 값은 0.02초 단위로 양자화된다.

방향 반전 가속도 95는 속도 부호가 반대인 구간에만 적용된다. +5→0은 약 0.053초이고, 이후 0→-5는 지상 65 또는 공중 22를 쓴다. 전체 반전 근사는 지상 0.130초, 공중 0.280초다. +5→-5 전체를 95로 계산하면 잘못된다.

셀레스트는 같은 방향의 초과 속도를 일반 가속도보다 느리게 감쇠한다. Ember에는 별도 초과 속도 감쇠가 없다. 단, 대시 종료 후 0.08초, 불에서 발사 후 0.25초의 launchProtection 동안 X 제어를 건너뛰고 운동량을 유지한다. 이후에는 같은 방향 입력이면 공중 22, 입력 없으면 14로 목표 속도에 접근한다. 이 때문에 공중에서 같은 방향을 누를 때보다 손을 놓았을 때 높은 속도가 더 오래 남을 수 있다.

### 확인된 수평 입력 결합

ReadHeldDirection은 X와 Y 방향을 합친 뒤 정규화한다. Update는 그 결과의 X를 horizontalInput에 사용한다. 따라서 오른쪽만 누르면 X=1이지만 오른쪽+위를 누르면 X≈0.707이다. 이동 5가 약 3.54, 이동 4.5가 약 3.18로 줄어든다. 아래 방향키도 같다.

코드상 감소는 확정이다. 이것이 의도된 설계인지 확인이 필요하지만, 수평 이동 속도를 일정하게 유지하려는 플랫폼 게임에서는 조준 중 거리 예측을 어렵게 만드는 동작이다. 수평 입력은 독립적인 -1/0/+1로 읽고, 조준·대시 방향만 정규화하는 방식으로 분리할 수 있다.

근거: `FlamePlayerController.cs:273`, `:340`, `:504`, `:616`.

## 3. 점프·이단점프·중력

코요테 타임과 입력 버퍼는 각각 0.12초다. 접지하면 코요테 타임·공중 점프 수·C 사용 가능 여부를 회복한다. 점프 입력이 남아 있고 코요테 시간이 양수이면 일반 점프, 아니면 공중 점프가 남았을 때 이단점프한다. 공중 점프는 기본 1회다. 발판에서 그냥 걸어 떨어져 코요테 시간이 끝나도 공중 점프 1회는 남는다.

점프는 Y 속도를 새로 설정하고 X에는 보너스를 더하지 않는다. 이단점프도 같은 초기 Y를 사용하여 기존 상승·하강 속도를 덮어쓴다. 셀레스트의 JumpHBoost=40에 대응하는 일반 점프 수평 부스트는 없다.

### jumpSpeed와 실제 출발 속도는 다르다

GetJumpLaunchSpeed는 아래 공식을 사용한다.

`launchY = sqrt(threshold² + (jumpSpeed² − threshold²) × riseGravityMultiplier)`

프리팹 기준 `jumpSpeed=7`, threshold=0.5, rise=1.4이므로 실제 출발 Y는 약 8.276이다. `1` 씬은 6, 0.5, 1.248이므로 약 6.698이다. 상승 중력을 더 크게 쓰면서 정점 임계 속도까지의 이상적인 상승 높이를 유지하려는 보정이다.

### 버튼을 놓으면 속도를 자른다

normalJump 중 Z를 놓고 Y가 양수이면 `vy = min(vy × 0.5, jumpSpeed × 0.5)`를 적용한다. 프리팹에서는 최대 3.5, `1`에서는 최대 3이다. normalJump와 jumpRiseActive도 해제한다. 셀레스트는 최대 0.2초 초기 상승 속도를 유지하는 방식이고 Ember는 릴리스 시 즉시 상승 속도를 줄이는 방식이다. 짧은 입력에 대한 높이 응답이 달라진다.

### 중력 우선순위

접지면 기본 중력. 공중에서 Z를 누르고 |vy|≤threshold이면 정점 배율. 그 밖에 하강 중이면 낙하 배율. 정상 점프 상승 중이고 임계 속도보다 빠르면 상승 배율. 나머지는 기본 중력이다.

프리팹 중력은 9.81×1.8=17.658이다. 상승 1.4배면 24.7212, 정점 0.85배면 15.0093, 낙하 1.3배면 22.9554다. `1` 씬 상승 중력은 약 22.0372다.

현재 정점 임계값은 코드 기본 2.2보다 훨씬 작은 0.5이며 중력 감소도 50%가 아니라 15%다. 정점 ±0.5 구간의 이상적 통과 시간은 약 0.067초, 물리 3~4스텝이다. 현재 프리팹은 코드 기본값에서 예상하는 것보다 정점 체공 보정이 약하다.

발판·충돌 없이 버튼을 유지하는 연속시간 모델에서 프리팹의 점프 높이는 약 1.389, 정점 시간은 약 0.348초다. `1` 씬은 높이 약 1.021, 정점 약 0.315초다. 이는 런타임 실측이 아니다. 첫 지상 점프 스텝의 grounded가 여전히 true라서 처음에는 기본 중력을 쓰고, 이후엔 50Hz 물리 적분과 접촉 판정이 개입한다.

### 착지 버퍼와 이단점프의 관계

착지 직전에 점프를 눌렀을 때 공중 점프가 남아 있다면, 버퍼가 착지를 기다리는 대신 즉시 공중 점프에 소비될 수 있다. 공중 점프를 이미 쓴 경우에는 착지 후 버퍼 점프가 가능하다. 설계상 자연스러운 우선순위지만, 점프 버퍼를 평가할 때 두 상황을 나누어 검사해야 한다.

## 4. 접지와 모서리 보정

접지 조건은 vy≤0.1이며 IsGrounded의 발밑 BoxCastAll에서 메인 플레이어 콜라이더·트리거 외의 콜라이더를 찾는 것이다. 검사 폭은 메인 콜라이더 bounds의 80%, 박스 높이는 0.05, 거리 0.12다. 발밑 근처 바닥을 실제 접촉 전에 접지로 취급할 수 있으며 공간 유예와 시간 유예가 함께 존재한다.

접지 전용 레이어와 히트 법선 검증은 없다. 따라서 범위에 들어온 고체가 실제로 발을 받치는 바닥인지 확인하지 않는다. 특정 모서리·사이드 접촉에서 공중 점프나 C가 예상보다 일찍 회복될 가능성은 있지만, 해당 장면은 플레이 모드에서 재현해야 한다.

머리 충돌 보정은 Free 상태에서 상승 중 천장 법선 Y<-0.65를 감지하면 실행된다. 입력 방향 또는 facing 방향을 우선하여 양쪽으로 0.04씩 최대 0.24를 탐색한다. 성공하면 X를 옮기고 Y를 0.03 올린 뒤 충돌 전 상승 속도를 복구한다. 한 번의 점프 중 보정은 1회로 제한한다.

빈 공간 검사는 실제 콜라이더 자체가 아니라 bounds의 폭 88%·높이 94%인 작은 OverlapBox다. 따라서 검사 성공이 전체 콜라이더의 무겹침까지 보장하지는 않는다. 좁은 천장·벽에서 복구 후 재충돌하거나 흔들리는지는 실측이 필요하다.

벽 충돌 속도 기억은 0.06초다. 같은 방향 입력이 있어야 복구하며 반대 입력이면 취소한다. 벽이 0.05 이내 캐스트에서 사라지고 현재 속도가 저장 속도보다 작으면 복구한다. 셀레스트와 달리 방향 입력이 없으면 복구하지 않는다.

근거: `FlamePlayerController.cs:463`, `:478`, `:554`, `:579`, `:604`.

## 5. C→Z 대시

C는 Free 상태에서 사용 가능 자원을 소비하고 주변 가연물을 점화한 뒤 Bursting으로 바꾼다. 속도·중력을 0으로 만들고 현재 설정 기준 0.3초간 행동을 선택한다. 지상·공중에서 사용 가능하며, Free 상태의 접지 또는 불꽃 진입에서 자원이 회복된다.

링 안의 Z는 점프 대신 대시다. 방향 입력이 없으면 위쪽으로 출발한다. Z가 대시 상태 진입 이후에 눌려야 하므로 C와 Z를 같은 프레임에 누른 경우 C 이후의 Z 분기가 자동 실행되는 구조가 아니다. Router의 해당 Free 분기는 C 요청 후 끝난다.

| 대시 파라미터 | 현재 프리팹 값 |
|---|---:|
| 최대 속도 | 16 |
| 가속 시간 | 0.05초 |
| duration | 0.15초 |
| 정상 종료 속도 배율 | 0.55 |
| 종료 상승 속도 상한 배율 | 0.22 |
| 종료 후 X 제어 제한 | 0.08초 |
| 방향 보정 검사 거리 | 0.45 |
| 방향 보정 간격·횟수 | 22° × 최대 3 |

대시는 정지에서 가속하므로 원래 운동량은 보존하지 않는다. 기본 0.02초 스텝에서 설정하는 속도는 처음 6.4, 다음 12.8, 다음 16이다. duration 감소도 같은 FixedUpdate에서 수행하므로 0.15초는 보통 8스텝(0.16초)에 종료된다. 마지막 스텝에는 16을 설정한 뒤 곧바로 종료 속도를 덮어쓴다.

장애물이 없는 수평 대시를 단순 속도 적분하면 앞 7스텝 거리 약 1.984이고, 8번째 종료 스텝 속도 8.8까지 포함하면 약 2.16이다. 코드를 옮겨 계산한 예상치이며 실제 Unity 실행 측정이 아니다. nominal 16×0.15=2.4를 실제 이동 거리로 간주하면 가속·종료 순서가 빠진다.

정상 수평 종료는 8.8이다. 위쪽 종료는 Y≤3.52로 제한한다. 아래쪽은 이 양수 상한에 걸리지 않아 Y=-8.8이 가능하다. 장애물에 막히면 X/Y 모두 0이 된다. 종료 후 X 보호 시간 동안에는 좌우 입력으로 방향을 바꾸지 못하지만 중력은 다시 적용된다. 변수 이름 launchProtection은 이 코드에서 무적을 의미하지 않는다.

### 입력 방향을 바꾸는 장애물 보정

TryBegin에서 desiredDirection이 막혀 있으면 +22°, -22°, +44°, -44°, +66°, -66° 순서로 검사하여 처음 비어 있는 방향을 선택한다. 입력이 8방향이어도 실제 대시 방향은 다른 각도가 될 수 있다. 양쪽이 모두 가능하면 +각도가 우선된다. 대시 도중 재탐색은 하지 않는다.

이는 셀레스트의 위치 이동을 통한 모서리 보정과 다르다. 지상 수평 입력이 바닥에 막힌 것으로 판정되면 위쪽으로 기울어진 경로를 선택할 가능성도 있다. 명시적인 보조 의도는 Tooltip에서 확인되므로 버그라고 단정하지 않지만, 최대 66° 변경은 정밀 조작에서 반드시 검토할 설정이다.

### 작은 대시 콜라이더

프리팹에는 자식 `Dash Collider` CircleCollider2D가 연결되어 있다. 시작하면 메인 콜라이더를 끄고 원형 콜라이더를 켠다. 종료 시 원래 메인 콜라이더를 복구한다. 작은 대시 콜라이더로 통과한 틈에서 전체 콜라이더를 다시 켜도 안전한지 검사하는 별도 분기는 없다. 좁은 통로에서 종료할 때 겹침·재충돌 위험은 검증이 필요하다.

## 6. X 흡수 이동·불꽃 발사

현재 불꽃 대상 탐색 반경은 4, 속도 19.5, 가속 시간 0.07초다. 방향 일치도와 거리로 목표를 평가하며 fireTargetDirectionDot=0.026이라 약 88.5°까지 후보가 될 수 있다. 따라서 거의 전방 반원 안의 불꽃이 대상이 된다. 대상이 막혔더라도 선택 가능하며 실제 이동 중에는 장애물 앞에서 멈추도록 되어 있다.

이동은 현재 위치에서 목표까지의 직선 또는 하나의 경유점을 갖는 경로다. 경로 검사는 플레이어 크기 75%의 BoxCastAll로 수행한다. 직선이 막히면 수직 방향으로 0.25 간격·최대 1 범위에서 경유점을 찾는다. 첫 성공 offset을 선택하고 같은 offset의 후보 중 짧은 경로를 고른다. 실제 이동 단계에서는 전체 Collider.Cast로 다시 확인하므로 축소 검사와 실제 통과 판정의 차이로 중간 정지가 발생할 수 있다.

MovePosition으로 이동하고 거리 제곱≤0.03이면 목표 근처로 인정한다. 즉 거리 임계값은 0.03이 아니라 sqrt(0.03)≈0.173이다. 불꽃에 들어가면 목표 위치로 옮기고 콜라이더를 끄며 스케일을 0.45로 바꾼다. 공중 점프 수와 C 사용권을 회복한다.

불꽃 안의 Z는 방향×launchSpeed로 발사한다. 무입력이면 위다. 프리팹/1/2에서는 속도 10, SampleScene은 12다. 초기 발사 위치는 방향으로 0.7 이동하며, 안전 검사에 실패하면 측면 최대 0.24까지 대체 위치를 찾는다. 발사 후 0.25초 동안 X 조절을 제한하며 정상 점프 플래그는 false라 점프 릴리스에 의한 속도 절반 감소는 적용하지 않는다.

흡수·대시·불꽃 내부에서 메인 Update는 Free용 jumpHeld/jumpReleased/horizontalInput을 갱신하지 않는다. 능력 방향은 Router에서 별도로 읽는다. Free 복귀와 렌더 Update의 순서에 따라 첫 물리 스텝에서 이전 jumpHeld가 정점 중력 선택에 사용될 수 있다. 이러한 상태 전환 영향은 정적 코드상 가능성으로 구분하고 실제 재현이 필요하다.

근거: `FlamePlayerController.cs:936`, `:1093`, `:1174`, `:1225`, `:1284`, `:1304`; `PlayerAbilityInputRouter.cs:34`.

## 7. 이동 발판과 애니메이션

PathMovingBlock은 Kinematic Rigidbody2D를 경로에 따라 MovePosition으로 이동한다. 컨트롤러에는 발판의 이동량을 플레이어에게 전달하거나 발판 속도를 점프에 더하는 별도 LiftBoost 계층이 없다. Unity 접촉과 마찰에서 발생하는 이동과 셀레스트의 명시적인 운반·발판 운동량 보존은 구분해야 한다. 실제 수평/수직 발판 위 안정성과 발판 점프는 실행 검증이 필요하다.

PlayerAnimatorDriver는 Rigidbody의 실제 X 속도로 좌우 스프라이트를 뒤집고 runSpeed=5로 정규화한다. 공중일 때는 상승/정점/낙하를 나누지 않고 같은 Blend Tree 임계값 2를 전달한다. 움직임에 비해 점프 애니메이션이 단조롭게 보인다면 물리 코드와 애니메이션 상태 선택을 분리하여 검토해야 한다. 프리팹 Animator Root Motion은 꺼져 있다.

근거: `PathMovingBlock.cs:33`, `:84`; `PlayerAnimatorDriver.cs:30`; `Assets/prefab/player.prefab:10073`, `:10180`.

## 8. 셀레스트와의 비교

| 관점 | 셀레스트 공개 코드 | 현재 Ember |

Ember의 핵심 이동은 이단점프와 C 공중 정지, X 불꽃 거점, 불꽃에서 발사하는 연속 동작이다. 셀레스트와 같은 기술을 억지로 넣지 않아도 이 이동 체계에 맞는 리듬을 만들 수 있다. 개선 여부는 Ember의 목표 조작감과 단계별 이동 거리의 일관성을 기준으로 결정해야 한다.

좋은 기반은 입력 버퍼·코요테 타임이 이미 존재하고, 능력 입력·대시 동작이 분리되어 있으며, 대시/흡수 이동에 사전 캐스트와 충돌 중단 경로가 있다는 점이다. 다음 작업은 M1 확인 → M2 의도 결정 → M3/M4 실행 검증 → 씬 설정 일관성 확인 순서가 효율적이다.
