# Ember — 현재 개발 방향 역기획서

> 이 문서는 2026-09-29 기준 대화에서 정한 최신 방향과 현재 프로토타입을 모아 재구성한 기획서다. 오래된 신화 서사 기획이나 아직 검증되지 않은 아이디어를 확정 사양으로 취급하지 않는다.

## 1. 게임 개요

- **작업명:** Ember
- **장르:** 2D 정밀 플랫포머 / 환경 퍼즐
- **플레이어:** 불 그 자체인 작은 불꽃 정령 앰버
- **한 줄 소개:** 앰버가 주변에 불을 붙여 이동 거점을 만들고, 불꽃에 흡수되었다가 튀어나오며 방을 돌파하는 2D 플랫포머.
- **핵심 감정:** 점프와 방향 조작의 손맛, 불을 연결해 새 경로를 만드는 발견, 위험한 선택 경로를 완수하는 성취감.

셀레스트는 조작감과 룸 단위 구성의 참고작이지, 그대로 복제할 목표는 아니다. Ember의 차별점은 대시만이 아니라 **불을 이동 경로로 만들고, 그 경로를 직접 연결하는 플레이**다.

## 2. 디자인 원칙

1. **조작이 먼저 재미있어야 한다.** 걷기, 점프, 이단점프, 공중 제어와 대시·흡수의 반응성을 먼저 다듬는다.
2. **불은 공격보다 이동과 퍼즐의 매개체다.** 불붙은 횃불은 이동 노드이며, 기믹 횃불은 블록이나 문 같은 환경을 작동시킨다.
3. **플레이어가 직접 경로를 만든다.** 불을 어디에 붙이고 어느 불을 연결하느냐가 방을 푸는 방법이 된다.
4. **작은 제작 규모를 지킨다.** 전투·복잡한 성장·대량의 고유 아트보다 재사용 가능한 타일과 룸 기믹을 우선한다.
5. **시각 정보는 명료하게 한다.** 앰버와 불은 어두운 배경에서 잘 읽히고, 위험물·이동 가능 거점·목표는 서로 구분되어야 한다.

## 3. 핵심 플레이 흐름

**방을 살핀다 → 이동·점프한다 → C로 불꽃을 터뜨려 주변 가연물이나 횃불에 불을 붙인다 → 불붙은 곳을 이동 거점으로 삼는다 → X로 흡수하고 방향을 골라 Z로 튀어나온다 → 필요하면 불꽃 대시로 간격을 넘는다 → 출구에 도달한다.**

기억의 불씨 같은 수집품은 주 경로를 막는 필수 열쇠가 아니라, 위험하거나 정교한 이동을 요구하는 선택 도전으로 둔다.

## 4. 플레이어 조작 및 이동 능력

현재 프로토타입의 기본 입력은 방향키와 Z/X/C다. 입력은 마우스 조준이 아니라 키보드 방향 선택을 중심으로 한다. 능력별 해금 컴포넌트가 있으나, 실제 스테이지 진행에서 어떤 능력을 언제 해금할지는 아직 확정하지 않았다.

| 입력 | 현재 역할 / 설계 의도 |
|---|---|
| 방향키 | 지상·공중 이동, 불꽃 대시와 발사 방향 선택, 불 안에서 다음 불 선택 |
| Z | 점프·이단점프. 불에 흡수된 동안에는 선택한 방향으로 발사. 불꽃 링 중에는 해금 시 대시 입력 |
| X | 불붙은 횃불로 흡수. 불꽃 링 중에는 누르고 방향을 골라 불씨를 쏘는 선택 능력 |
| C | 주변 상호작용을 먼저 확인한 뒤, 일반 상태에서는 플레이어 위치에서 즉시 원형 불꽃 폭발 |

### 이동 능력의 규칙

- **기본 이동:** 가속·감속, 공중 제어, 코요테 타임, 점프 입력 버퍼, 이단점프로 정밀한 플랫폼 조작을 지원한다.
- **불꽃 폭발(C):** 눌렀을 때 폭발 자체는 즉시 발생한다. 이후 짧은 정지/선택 시간 동안 X로 조준 사격하거나 Z로 불꽃 대시를 하는 조합은 프로토타입에 존재한다. 이 후속 조합이 최종 플레이에 필요한지는 검증 대상이다.
- **불 흡수(X):** 불붙은 횃불을 선택해 빠르게 이동하며, 이동 전 시각 안내선으로 목적지를 알려준다. 불 안에서는 방향키로 인접한 다음 불을 고를 수 있다.
- **불꽃 발사(Z):** 불 안에서 방향을 정해 튀어나온다. 벽을 통과하지 않고 장애물에 닿으면 멈추며, 작은 모서리는 제한적으로 보정한다.
- **불꽃 대시(C 후 Z):** 플레이어가 직접 발동하는 이동 능력. 장애물을 무시해 통과하는 능력이 아니라, 제한된 보정으로 가까운 모서리를 피하고 충돌 시 안전하게 멈추는 방향이다.
- **불씨 사격(X 길게 누른 뒤 놓기):** 코드상 조준 보조와 시간 감속을 포함한 실험 기능이다. 전투를 위한 필수 공격이 아니며, 멀리 있는 횃불 점화에 실제로 도움이 되는지 확인한 후 유지 여부를 정한다.

## 5. 불과 환경 기믹

### 핵심으로 유지할 기믹

- **불붙는 요소:** 횃불, 나무·풀·밧줄·넝쿨처럼 의도된 가연물만 불이 붙는다. 모든 지형 타일이 타는 방향은 피한다.
- **횃불 이동망:** 불이 붙은 횃불은 앰버가 흡수할 수 있는 이동 거점이다. 새 불을 켜면 갈 수 없던 경로가 열린다.
- **기믹 횃불과 이동 블록:** 기믹 횃불에 불을 붙이면 미리 배치한 보이지 않는 직선·곡선 경로를 따라 블록이 움직인다. 경로는 씬에서 직접 배치·편집하는 방식이 목표다.
- **위험물과 리스폰:** 스파이크 등 접촉 위험물에 닿으면 체크포인트로 돌아간다. 사망 뒤 방을 빠르게 다시 시도할 수 있어야 한다.
- **룸 카메라:** 방마다 카메라 이동 범위를 지정하고, 방 전환과 플레이어 추적이 플레이를 방해하지 않도록 조정한다. 셀레스트의 카메라 감각을 참고하되 전환 연출과 경계 동작은 계속 검증한다.

### 추가 후보 — 코어 조작 검증 이후

- **횃불 문·순서 퍼즐:** 모든 횃불 점화 또는 정해진 순서대로 점화해 문을 연다.
- **성화 지점 상호작용:** 특정 지점에서 C를 눌러 연결된 횃불이나 장치를 작동시킨다. Trial Altar 기반은 프로토타입에 있으나 최종 연출·규칙은 미정이다.
- **불꽃 바람 분출구:** 분출구에서 C로 상호작용해 한 방향으로 불꽃 바람을 보내, 직접 닿기 어려운 횃불을 켠다. 플레이어를 강화하는 별도 성장 시스템과는 구분한다.
- **불붙는 로프·넝쿨 스윙:** 불을 붙인 줄에 흡수되어 방향키로 좌우 반동을 만든 뒤, 원하는 방향으로 발사한다. 구현 난도가 높아 기본 이동 검증 후 판단한다.
- **자유 비행 지점:** 특정 장소에서 상호작용해 짧은 시간 중력의 영향을 덜 받는 자유 이동을 제공한다. 신화 명칭과 규칙은 미정이다.
- **꺼지는 불·상승하는 물:** 물이나 비에 의해 불이 꺼지는 방, 바닥에서 물이 올라오는 탈출 방은 별도 스테이지 기믹 후보로 보류한다.

## 6. 스테이지와 방 구성

- **목표 규모:** 4개 스테이지, 스테이지당 약 15개 방(총 약 60개 방)을 목표로 생각 중이다. 완성 보장은 아니며, 일정에 따라 줄일 수 있는 확장 목표다.
- **제작 순서:** 60개 방을 한 번에 만들지 않는다. 먼저 코어 조작이 완성된 3~5개 방의 세로형 시제품을 만든다. 그 방이 재미있고 안정적일 때 스테이지와 방을 늘린다.
- **초반 방:** 이동·점프를 익히고, C로 불을 만들고, X/Z로 불을 이동 거점으로 쓰는 법을 안전한 상황부터 가르친다.
- **중후반 방:** 기존 능력을 조합하고, 불의 위치·횃불·위험물·움직이는 블록을 이용한 선택 경로와 숙련자용 도전을 제공한다.
- **스테이지 차이:** 모든 스테이지에 새로운 핵심 시스템을 강제로 추가하지 않는다. 같은 타일셋을 재사용하고 배경, 색감, 장식, 기믹 조합으로 분위기를 달리한다.

## 7. 아트 및 화면 방향

- 그리스 신들의 시련·제우스·헤파이스토스 중심의 서사는 현재 범위에서 제외한다. 남기는 것은 **작은 불꽃의 모험**이라는 분위기뿐이다.
- 목표 이미지는 어둡고 깊이 있는 폐허·동굴 배경과 따뜻하게 빛나는 앰버·불꽃의 대비다. 그리스 신화 고증이나 신전 테마는 필수 조건이 아니다.
- 플레이 충돌용 타일맵과 장식 아트를 분리한다. 타일맵은 충돌과 룸 블록아웃을 담당하고, 배경·중경·전경은 별도 스프라이트/타일 레이어와 패럴랙스로 깊이감을 만든다.
- 기본 타일셋을 여러 스테이지에서 재사용하고, 조명·색감·식생·배경 레이어로 변주한다.
- `ArtReference/amber-character-concept.png`는 앰버의 단일 캐릭터 콘셉트 이미지다. 최종 인게임 스프라이트와 대기·달리기·점프·체공 애니메이션은 아직 별도 제작·검증이 필요하다.

## 8. 서사와 수집 요소

- **서사 범위:** 신화 인물, 보스 서사, 긴 대화는 축소·제외한다. 앰버가 왜 모험하는지와 결말은 현재 미정이며, 게임을 완성하는 데 필요한 최소한의 분위기 전달만 고려한다.
- **기억의 불씨:** 딸기나 신의 눈처럼 플레이타임과 재도전을 늘리는 선택 수집품의 작업명이다. 메인 경로 완수에 강제하지 않고, 어려운 경로 보상으로 배치하는 방향이다. 저장·보상 규칙은 미정이다.

## 9. 현재 상태와 우선순위

### 프로토타입에 기반이 있는 요소

- 방향키 이동, 점프·이단점프와 조작 보정
- C 불꽃 폭발, 불 흡수·불에서 발사, 불꽃 대시, 선택적 불씨 사격의 코드 기반
- 불 흡수 목적지 안내, 잔상·파티클·빛 피드백
- 방 카메라, 위험물 리스폰, 경로 이동 블록, 기믹 횃불/제단 기반

위 항목은 코드나 장면에 기반이 있다는 뜻이지, 완성·밸런스 검증이 끝났다는 의미는 아니다.

### 개발 우선순위

1. **조작 검증:** 점프·이단점프·C 폭발·X 흡수·Z 발사·C+Z 대시가 자연스럽고, 키 입력끼리 충돌하지 않는지 확인한다.
2. **안정성:** 벽 끼임·벽 통과·카메라 전환 문제를 잡고, 죽음과 체크포인트 재시작을 매끄럽게 한다.
3. **작은 완성 방 묶음:** 흡수 이동과 기믹 횃불-이동 블록을 활용하는 짧은 구간을 만든다.
4. **완성도와 확장 판단:** 애니메이션·사운드·기억의 불씨를 더하고, 플레이테스트 뒤 방 수와 추가 기믹을 확정한다.

## 10. 범위에서 제외하거나 보류하는 것

- 적·전투 중심 게임플레이
- 그리스 신화 신들을 수집·인증하는 장편 서사와 최종 보스
- 불씨→불꽃→화염 같은 복잡한 성장 단계
- 마우스로 캐릭터를 조준·이동하는 조작
- 대시로 벽과 장애물을 무조건 관통하는 규칙
- 코어 이동이 재미있는지 확인하기 전에 모든 후보 기믹을 구현하거나 60개 방을 제작하는 것

## 11. 아직 확정하지 않은 결정

1. 4×15개 방 목표가 실제 행사 빌드 범위에 맞는지, 먼저 몇 개의 방을 완성할지
2. 불씨 사격을 핵심에 둘지, 불꽃 대시와 횃불 흡수만으로 충분한지
3. 바람·스윙·자유 비행·꺼지는 불·상승하는 물 중 행사 빌드에 넣을 기믹
4. 기억의 불씨 수집 보상과 저장 방식
5. 픽셀풍과 손그림풍 중 최종 아트 스타일, 그리고 앰버의 애니메이션 시트
6. 스테이지별 배경 테마와 앰버의 여행 목적·결말

**기획의 최종 판단 기준:** 새 아이디어를 더하기 전에, 작은 한 방에서 이동과 불의 연결만으로도 다시 도전하고 싶은 재미가 생기는지 먼저 확인한다.
