# 스프링 배치

1. 빈 오브젝트 또는 스프링 그림을 가진 오브젝트를 만들고 `Spring` 컴포넌트를 추가한다.
2. 자동으로 추가되는 `BoxCollider2D`를 윗면의 얇은 영역으로 맞춘다. 시작 예시는 가로 1, 세로 0.2 월드 단위다. Collider는 Trigger로 설정된다.
3. `Bounce Speed`로 위쪽 추진 속도를 조절한다. 기본은 10 U/s다. `Top Tolerance`는 위에서 접촉하는 판정 여유이며 기본 0.08 U다.
4. `On Bounce` 이벤트에 스프링 애니메이션이나 효과음을 연결할 수 있다. 그림·사운드는 스크립트가 자동 생성하지 않는다.

플레이어가 위에서 낙하하며 닿으면 자동으로 튕긴다. 상승·옆면·아래쪽 접촉, 불 흡수·대시·링 상태, 제단 입력 잠금 중에는 튕기지 않는다. 좌우 속도를 유지하고 공중 점프와 링 사용권을 회복한다. 점프 버튼을 놓아도 스프링의 상승 속도는 잘리지 않는다.

스프링 자체는 고체 바닥이 아니다. 받침대가 필요하면 별도 고체 Collider를 아래에 배치하고, Trigger의 윗면이 고체 바닥보다 조금 높게 나오도록 한다. 기존 플레이어에는 필요한 연결 코드가 들어 있어 Inspector 참조를 추가로 연결할 필요가 없다. 기존 씬에는 자동 배치하지 않는다.

회귀 검증은 `Validation/Movement/SpringTests.cs`에 있다. 실제 트리거 처리 함수를 호출하고 네이티브 Physics2D로 상승·추가 점프를 확인한다. 그림과 연출, 실제 씬 배치는 Unity Game 화면에서 확인한다.

Unity 6000.5.3f1의 격리 EditMode 검증: **35개 통과 / 실패·건너뜀 0개**. 스프링 6개, 기존 입력·이동·벽 낙하 19개, 발판 운반 10개다. 런타임 27개 소스가 컴파일됐다. 별도 Tilemap fixture 검증과 실제 씬 손 플레이는 포함하지 않는다. 결과는 `ValidationArtifacts/MovementFeel/Spring/UnityResults.xml`에 있다. 기존 임시 프로젝트의 패키지 캐시 참조 오류가 있어 새 `%LOCALAPPDATA%/Temp/EmberSpringQA-20261005` 프로젝트에서 검증했다. 원본 프로젝트 패키지는 변경하지 않았다.
